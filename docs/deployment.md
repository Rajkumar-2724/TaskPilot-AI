# Deployment

The project includes a `render.yaml` Blueprint for [Render](https://render.com/docs/blueprint-spec)
defining two services (backend web service + frontend static site) and a
MongoDB cluster dependency.

## Architecture on Render

| Service | Type | Command |
|---|---|---|
| `taskpilot-ai-backend` | Web Service (Node 18+) | `cd backend && npm install && npm start` |
| `taskpilot-ai-frontend` | Static Site | `cd frontend && npm install && npm run build` (output: `dist/`) |
| MongoDB | Managed cluster | Mongo 6+ (Render or MongoDB Atlas) |

The Python ML service can run as a third Render web service, or on a
separate VM / container, or be omitted entirely — the backend transparently
falls back to its in-app engine for predictions.

## Environment variables (Render dashboard)

### Backend

| Variable | Required | Notes |
|---|---|---|
| `PORT` | auto-set | Render sets `PORT`; do not override |
| `NODE_ENV` | Yes | `production` |
| `MONGO_URI` | Yes | Mongo 6+ connection string |
| `JWT_SECRET` | Yes | Auto-generated by Render Blueprint |
| `CLIENT_URL` | Yes | Frontend URL (e.g. `https://taskpilot-frontend.onrender.com`) |
| `GEMINI_API_KEY` | Optional | For Gemini-powered features |
| `GEMINI_MODEL` | Optional | Default `gemini-1.5-flash` |
| `ML_SERVICE_URL` | Optional | URL of the Python ML service; omit for built-in fallback only |
| `CLOUDINARY_*` | Optional | For profile/uploads |
| `SMTP_*` | Optional | For email notifications |

### Frontend

| Variable | Required | Notes |
|---|---|---|
| `VITE_API_URL` | Yes | Backend base URL + `/api` (e.g. `https://taskpilot-backend.onrender.com/api`) |

### ML service (if deployed)

| Variable | Default | Notes |
|---|---|---|
| `HOST` | `0.0.0.0` | |
| `PORT` | `8000` | Render sets `PORT`; override if needed |

No API keys are required for the Python ML service.

## Steps

1. Push this repo to GitHub.
2. In Render, click **New → Blueprint**, select the repo.
3. Render provisions the backend and frontend from `render.yaml`.
4. Create a MongoDB cluster (Render Managed MongoDB **or** MongoDB Atlas)
   and paste its connection string as `MONGO_URI`.
5. Set `CLIENT_URL` to the frontend URL and `VITE_API_URL` to the backend
   URL + `/api`.
6. (Optional) Add `GEMINI_API_KEY`, `CLOUDINARY_*`, `SMTP_*`, and
   `ML_SERVICE_URL` as needed.
7. Trigger deploy.

## Local development

```bash
# 1. Start MongoDB locally (mongod on :27017)

# 2. Backend
cd backend && npm install && npm run dev

# 3. Frontend
cd frontend && npm install && npm run dev

# 4. ML service (optional but recommended)
cd ml-service && pip install -r requirements.txt && python main.py
```

The backend will start cleanly even if MongoDB is not running (it will log
a warning and allow the Express server to respond to requests that don't
touch the database).
